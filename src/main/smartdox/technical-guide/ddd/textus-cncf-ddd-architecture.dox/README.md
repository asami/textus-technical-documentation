## Purpose and reader

This guide explains SimpleModeling and Textus/CNCF through DDD concepts and
design concerns. It provides conceptual entry points into the whole system.
General modeling procedures belong to separate documentation. Prose describes
responsibilities and connections without a DDD-deficiency or superiority narrative.

## Reading order

1. Purpose and scope.
2. Three-book sources, selected terminology and adopted meanings.
3. System overview through DDD and CQRS.
4. Strategic highlights: contexts/component boundaries, shared language and BoK links.
5. Tactical highlights: identity, shared Value Object meanings and Aggregate consistency.
6. CQRS update/read paths, persistence, Domain Events, Views and Displays.
7. Application progression and complementary models.
8. DDD model, generation, component and runtime connections.
9. Supplementary implementation and verification connections.
10. Concept and related-technique index.
11. References and actual inspection scope.

The first figure identifies DDD concepts, shared/supporting patterns and platform

diagram subjects. Value Objects connect to both routes. Context boundaries are
concretized as subsystem/component modeling boundaries under the adopted policy.

## Three-book comparison scope

English editions: Evans (2003), Vernon (2013), Khononov (2021). The guide records
chapter coverage and verified explanatory distinctions from published contents
and identified public excerpts, then states the meanings adopted for this system.
Uninspected full definitions and unproved omissions remain explicit. Public-source
inspection is not represented as an exhaustive full-text comparison. Bibliographic
source URLs and chapter locators are in the manuscript.
